# API-to-SQLite benchmark: timed local runs

The benchmark asks for a Python API-to-SQLite synchronizer from the same specification, plan, tasks, and public tests. The reference implementation passed all 39 public and hidden tests with 98.17% measured coverage. HTTP is mocked in tests and test databases are temporary or in memory. The application itself is designed to connect to an API when configured; the benchmark tests do not require one.

Each timed run allowed an initial generation and up to three repairs. After manual review, the project virtual environment ran the 27 public tests with a 90% coverage threshold. The final candidate was also checked against 12 hidden tests. The clock includes generation, testing, and manual review delays. These are single trials of direct Ollama generation with test-feedback prompting, not Pi-agent runs; they do not establish general model performance or time to a successful production implementation.

| Model | Wall time | Model calls (seconds) | Public result | Hidden result | Outcome |
| --- | ---: | --- | --- | --- | --- |
| Qwen3-Coder 30B | 1,014.78 s | 237.91, 293.36, 183.39, 189.03 | 24/27 passed on each attempt; 80% coverage | 5/12 passed | Fail |
| Qwen3.5 4B | 261.91 s | 51.89, 49.78, 38.33, 50.36 | Best attempt 21/27; final 0/27 | 0/12 on final | Fail |
| LFM2.5 8B | 162.73 s | 30.41, 22.72, 23.17, 22.52 | All attempts failed during collection | Final candidate failed during collection | Fail |

Qwen3-Coder 30B generated byte-identical code for all four attempts despite distinct prompts and public feedback. The repeated behavior is an observation, not a diagnosed cause. Its final candidate missed validation and error-handling cases. The Qwen3.5 run had three outputs stop at the 4,096-token limit, some with no usable code; all LFM calls hit that limit, and its outputs included incomplete or invalid Python. This common output budget and the prompt/extraction workflow may have materially affected the results. One earlier exploratory 30B repair passed the then-current public suite but failed 8 of 12 expanded hidden tests; those exploratory results are not directly comparable because tests changed during development.

No model achieved a passing result, so time to successful completion remains unknown. Qwen3-Coder 30B is the strongest candidate for a further batch-oriented investigation on this task, not a demonstrated autonomous production solution. Review the repeated-output behavior and test model-appropriate output/thinking settings before drawing a broader conclusion; use a new frozen protocol for any comparison. A single synthetic exercise and line coverage do not prove production readiness.

Raw prompts, responses, candidate files, test logs, and timings are under `benchmarks/api_sync/runs/` in the directories `2026_11_05__00_50_50_760374__timed__qwen3.5_4b`, `2026_11_05__00_55_23_311514__timed__lfm2.5_8b`, and `2026_11_05__00_58_17_261127__timed__qwen3-coder_30b`. Runs explicitly labeled synthetic are harness checks and excluded. Reproduction instructions are in `benchmarks/api_sync/README.md`; frozen input hashes are in `benchmarks/api_sync/input_hashes.sha256`.

A virtual environment is dependency isolation, not a security sandbox. Review generated code before executing it; the coordinator requires a review confirmation. No model was removed based on this limited trial.
